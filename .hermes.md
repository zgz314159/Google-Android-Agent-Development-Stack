# Hermes Project Context — Google Android Agent Development Stack

This file is **project context** for Hermes (orchestration kernel). It is **not** a Hermes
fork and contains no Hermes source. Hermes runs from the official upstream install; this
file only tells it how to behave inside this repository.

## System identity

1. This Stack is an **Android AI software-factory system**: it compiles a change request
   into a frozen Implementation Contract, then implements, verifies on a physical device,
   and evaluates.
2. The **Specification Compiler** is responsible for design (collect → normalize →
   cross-reference → validate → freeze → package). It never calls an LLM.
3. A **Frozen Contract** takes precedence over any Agent re-planning. The handoff
   artifacts are `implementation-contract.json`, `READY.json`, `manifest.json`, and
   `EXECUTOR-PROMPT.md`.

## Hermes role

4. Hermes is responsible for **orchestration / task decomposition / delegation / parallel
   scheduling**. It is the orchestration kernel between the Contract and the Executor.
5. Hermes must **not reopen a frozen Contract decision**. Contracts carry
   `Frozen decisions (do not reopen)`; a contradiction is reported as
   `CONTRACT_DEVIATION`, never silently redesigned.

## Scope boundaries

6. **KeepLab production code** may only be modified during an official implementation
   phase (never during planning/spec/verification rounds).
7. **Testapp** and **PowerAi** are **never** in the current experiment scope.

## Delegation rules

8. **Read-only tasks**: parallel delegation is allowed.
9. **Write tasks**: single writer by default (one writer per file boundary).
10. Future **parallel implementation** must use worktree isolation per writer.

## Android device

11. The physical Android device **`87296ada`** (Redmi Note 7 Pro, API 36) is an
    **exclusive mutable resource** with **capacity = 1**.
12. Multiple Agents must **not** operate the same physical device concurrently. Acquire
    the host device lock (`verification/core/device_lock.sh`, `flock` on
    `device:<serial>`) before any deterministic device run.
13. The device **PASS path is deterministic execution with 0 visual LLM judgment**.
14. AI intervenes **only** on exploration, unexpected state, or FAIL evidence.
15. The normal PASS path must **not** use a `screenshot → LLM → tap` loop. Device
    interactions use selector-driven executors (Maestro / UiAutomator), never per-step
    LLM vision.

16. The official replay gate is **fail-fast**. The runner stops at the first
    deterministic failure, still flushes `result.json` + failure evidence + `index.json`,
    and exits non-zero. Hermes then inspects the failed step, Maestro output, hierarchy,
    screenshot and logcat **once**, applies a **minimal fix**, and re-runs **only the
    failed flow** (R1 fails → fix R1 → re-run R1 × 3; a frozen-PASS R2/R3 is never
    re-run). `--continue-on-fail` is a diagnostic mode, never the official gate.

## Reference replay

- External reference apps (Google Keep) are replayed with frozen Maestro flows under
  `verification/reference-replay/`. One command (`run_reference_replay.sh`) runs the whole
  flow; Hermes receives a compact result, not per-step frames.
- NORMAL PASS: `Hermes → one deterministic runner → compact result`.
- FIRST FAIL: the runner stops immediately; Hermes reads the FAIL evidence once, makes a
  minimal fix, and retries the failed flow only. The
  `screenshot → LLM → tap → screenshot` loop is forbidden in both paths.

## Proof tooling

17. Do not create per-phase ad-hoc scratch proof/hash/report scripts when `execute_code` or an
    existing checked-in deterministic utility can do the same job.

## Contract generation

18. **Generated Contract artifacts are compiler-owned.** The deterministic Specification
    Compiler (`specification/compiler/`) is the only producer of
    `implementation-contract.json`, `manifest.json`, `READY.json`, `EXECUTOR-PROMPT.md` and
    `validation-report.json`.
19. A model may author **only** the compiler's authored source artifacts — `PRODUCT.md`,
    `requirements.md`, `design.md`, `tasks.md`, `DESIGN.md`, `acceptance.md`,
    `project-context.json` and `verification-intent.json` — and then runs
    `hash_manifest.py` → `build_contract.py` → `validate_package.py`.
20. Never create or hand-patch a generated Contract artifact. If generation or validation
    fails, fix the authored input or the compiler source, never the generated output.
